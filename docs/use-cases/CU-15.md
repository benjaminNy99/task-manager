# CU-15: Gestionar el encargado de una tarea

| Campo | Descripción |
|---|---|
| Actor | Líder de proyecto o administrador. |
| Objetivo | Asignar, cambiar o retirar al encargado de una tarea. |
| Precondiciones | Actor autenticado mediante CU-02; existen el proyecto y la tarea identificada dentro de él. Para asignar un encargado, existe la cuenta destinataria. |
| Resultado esperado | Encargado actualizado, o tarea sin asignar por decisión autorizada; modificación registrada en logs. |
| Requerimientos | RF-04, RF-09, RF-10, RF-16, RF-17, RF-18, RF-22, RF-27, RF-28, RNF-02, RNF-03. |

**Flujo principal**

- **CU-15.1:** El actor identifica el proyecto por su sigla y la tarea por su identificador dentro del proyecto, e indica el usuario que desea asignar como encargado.
- **CU-15.2:** El sistema verifica que el actor sea líder con acceso al proyecto o administrador.
- **CU-15.3:** El sistema verifica que el usuario elegido tenga acceso al proyecto, incluido el acceso global de un administrador.
- **CU-15.4:** El sistema guarda al usuario indicado como encargado, sustituyendo al anterior si lo hubiera, sin cambiar el usuario registrado como creador.
- **CU-15.5:** El sistema registra la modificación conforme a RF-09 con los identificadores de tarea y proyecto e informa el resultado. Finaliza el caso.

**Flujos alternativos**

**CU-15.A1: Dejar la tarea sin encargado**

Desencadenante: paso CU-15.1, cuando el actor solicita retirar al encargado en lugar de asignar un usuario.

- **CU-15.A1.1:** El actor solicita que la tarea quede sin encargado.

Continuación: continúa en CU-15.2. Tras verificar la autorización, continúa en CU-15.4 guardando la tarea sin encargado y prosigue en CU-15.5; no se ejecuta CU-15.3 porque no hay usuario destinatario.

**Flujos de excepción**

**CU-15.E1: Actor sin permiso para gestionar encargados**

Desencadenante: paso CU-15.2, cuando el actor no es líder con acceso ni administrador, incluido un contribuyente sin capacidades superiores.

- **CU-15.E1.1:** El sistema rechaza la operación sin cambiar ni retirar al encargado.

Continuación: finaliza el caso.

**CU-15.E2: Encargado sin acceso al proyecto**

Desencadenante: paso CU-15.3, cuando el usuario elegido no tiene acceso al proyecto.

- **CU-15.E2.1:** El sistema rechaza la asignación sin cambiar al encargado existente.

Continuación: finaliza el caso.

**Consideraciones**

- La asignación automática al contribuyente que crea la tarea se documenta en [CU-12](CU-12.md).
- El requisito para el encargado es tener acceso al proyecto; no se exige un rol adicional que no esté establecido en RF-27.
