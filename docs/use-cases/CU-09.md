# CU-09: Modificar un proyecto

| Campo | Descripción |
|---|---|
| Actor | Líder de proyecto o administrador. |
| Objetivo | Actualizar el nombre o la sigla de un proyecto. |
| Precondiciones | Actor autenticado mediante CU-02; existe el proyecto identificado por su sigla. |
| Resultado esperado | Proyecto actualizado y modificación registrada en logs. |
| Requerimientos | RF-09, RF-10, RF-12, RF-16, RF-17, RF-18, RF-19, RNF-02, RNF-03. |

**Flujo principal**

- **CU-09.1:** El actor identifica el proyecto por su sigla y proporciona los cambios de nombre o sigla.
- **CU-09.2:** El sistema identifica el proyecto sin distinguir mayúsculas y minúsculas y verifica que el actor sea líder con acceso al proyecto o administrador.
- **CU-09.3:** Si cambia la sigla, el sistema valida que no tenga espacios ni caracteres especiales y que no coincida con la de otro proyecto, sin distinguir mayúsculas y minúsculas.
- **CU-09.4:** El sistema persiste los cambios, registra la modificación conforme a RF-09 e informa el resultado usando la sigla vigente. Finaliza el caso.

**Flujos de excepción**

**CU-09.E1: Operación no autorizada**

Desencadenante: paso CU-09.2, cuando el actor carece del rol o del acceso requerido.

- **CU-09.E1.1:** El sistema rechaza la operación sin modificar el proyecto.

Continuación: finaliza el caso.

**CU-09.E2: Sigla no válida o duplicada**

Desencadenante: paso CU-09.3, cuando la nueva sigla incumple las reglas de formato o unicidad.

- **CU-09.E2.1:** El sistema informa del incumplimiento sin guardar la modificación solicitada.

Continuación: finaliza el caso.

**Consideraciones**

- El conjunto exacto de caracteres permitidos en las siglas sigue pendiente en RF-12.
- Los cambios de acceso se documentan en [CU-11](CU-11.md), no como cambios del nombre o la sigla.
