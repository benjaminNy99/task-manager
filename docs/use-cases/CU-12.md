# CU-12: Crear una tarea

| Campo | Descripción |
|---|---|
| Actor | Contribuyente, líder de proyecto o administrador. |
| Objetivo | Registrar una tarea en un proyecto. |
| Precondiciones | Actor autenticado mediante CU-02; existe el proyecto seleccionado por su sigla. |
| Resultado esperado | Tarea persistida con identificador incremental independiente por proyecto, fecha automática, creador y encargado cuando corresponda; creación registrada en logs. |
| Requerimientos | RF-01, RF-02, RF-03, RF-04, RF-09, RF-10, RF-16, RF-17, RF-18, RF-20, RF-22, RF-27, RF-28, RNF-02, RNF-03. |

**Flujo principal**

- **CU-12.1:** El actor identifica el proyecto por su sigla y proporciona nombre, descripción, estado y prioridad de la nueva tarea.
- **CU-12.2:** El sistema verifica que el actor tenga capacidades de contribuyente y acceso al proyecto; el administrador dispone de acceso global.
- **CU-12.3:** El sistema valida que el estado sea «No empezado», «En curso» o «Completado», y que la prioridad sea un entero del 1 al 10.
- **CU-12.4:** El sistema asigna automáticamente el identificador entero positivo incremental dentro del proyecto, obtiene la fecha de ingreso del sistema, asocia la tarea al proyecto y registra al actor como creador.
- **CU-12.5:** El sistema asigna al creador como encargado de la tarea.
- **CU-12.6:** El sistema persiste la tarea, registra la creación conforme a RF-09 con los identificadores de tarea y proyecto e informa el resultado. Finaliza el caso.

**Flujos alternativos**

**CU-12.A1: Encargado elegido por un líder o administrador**

Desencadenante: paso CU-12.5, cuando el creador dispone de capacidades de líder o administrador y solicita asignar otro usuario o dejar la tarea sin encargado.

- **CU-12.A1.1:** El actor indica el encargado o solicita que la tarea quede sin asignar.
- **CU-12.A1.2:** Si se indica un encargado, el sistema verifica que tenga acceso al proyecto, incluido el acceso global de un administrador.
- **CU-12.A1.3:** El sistema utiliza la asignación indicada en lugar de la asignación al creador.

Continuación: continúa en CU-12.6.

**Flujos de excepción**

**CU-12.E1: Operación no autorizada**

Desencadenante: paso CU-12.2, cuando el actor carece del rol o del acceso requerido.

- **CU-12.E1.1:** El sistema rechaza la operación sin crear la tarea.

Continuación: finaliza el caso.

**CU-12.E2: Estado o prioridad no válidos**

Desencadenante: paso CU-12.3, cuando el estado no está admitido o la prioridad no es un entero del 1 al 10.

- **CU-12.E2.1:** El sistema informa del incumplimiento y no crea la tarea.

Continuación: finaliza el caso.

**CU-12.E3: Encargado sin acceso al proyecto**

Desencadenante: paso CU-12.A1.2, cuando el usuario elegido no tiene acceso al proyecto.

- **CU-12.E3.1:** El sistema rechaza la asignación solicitada y no guarda la nueva tarea con ese encargado.

Continuación: finaliza el caso sin completar la creación solicitada.

**Consideraciones**

- La asignación automática al creador se aplica a sus capacidades de contribuyente, incluidas las heredadas. Solo un líder o administrador puede elegir otra asignación o dejarla vacía.
- No se fija un estado ni una prioridad predeterminados: ambos forman parte de los datos proporcionados.
- Un identificador de tarea se interpreta junto con su proyecto, ya que puede repetirse en otros proyectos.
