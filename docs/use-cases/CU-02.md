# CU-02: Acceder a la aplicación

| Campo | Descripción |
|---|---|
| Actor | Usuario. |
| Objetivo | Identificarse y autenticarse para utilizar las operaciones que su cuenta tenga permitidas. |
| Precondiciones | Existe una cuenta para el usuario. |
| Resultado esperado | Usuario autenticado e identificado para comprobar sus permisos antes de consultar o persistir datos. |
| Requerimientos | RF-10, RF-14, RF-15, RF-23, RNF-02. |

**Flujo principal**

- **CU-02.1:** El usuario solicita acceso a la aplicación interactiva y proporciona su nombre y contraseña.
- **CU-02.2:** El sistema identifica la cuenta sin distinguir mayúsculas y minúsculas en el nombre y verifica la contraseña.
- **CU-02.3:** El sistema establece la identidad autenticada para las comprobaciones de permisos de las operaciones solicitadas. Finaliza el caso.

**Flujos alternativos**

**CU-02.A1: Autenticación de un comando**

Desencadenante: paso CU-02.1, cuando el usuario solicita una operación mediante un comando de terminal, distinto de la creación del administrador inicial.

- **CU-02.A1.1:** El usuario proporciona las credenciales mediante `--user` y `--pass` en el comando solicitado.
- **CU-02.A1.2:** El sistema comprueba que ambos parámetros estén presentes.

Continuación: continúa en CU-02.2. Este flujo se ejecuta en cada comando, aunque una invocación anterior haya sido autenticada.

**Flujos de excepción**

**CU-02.E1: Credenciales no válidas**

Desencadenante: paso CU-02.2, cuando no se identifica la cuenta o la contraseña no es válida.

- **CU-02.E1.1:** El sistema deniega el acceso y no ejecuta la operación solicitada.

Continuación: finaliza el caso sin autenticar al usuario.

**CU-02.E2: Faltan parámetros de autenticación**

Desencadenante: paso CU-02.A1.2, cuando falta `--user` o `--pass`.

- **CU-02.E2.1:** El sistema no ejecuta la operación solicitada e informa que se requieren ambos parámetros.

Continuación: finaliza el caso sin autenticar al usuario.

**Consideraciones**

- La autenticación no concede acceso por sí sola: cada operación comprueba roles y acceso al proyecto cuando corresponda.
- La única excepción a este requisito es [CU-01](CU-01.md). No se definen duración de sesión, cierre de sesión, bloqueo de cuentas ni recuperación de contraseñas.
