# CU-02: Acceder a la aplicación

| Campo | Descripción |
|---|---|
| Actor | Usuario. |
| Objetivo | Identificarse y autenticarse para utilizar las operaciones que su cuenta tenga permitidas. |
| Precondiciones | Existe una cuenta para el usuario. |
| Resultado esperado | Usuario autenticado, no bloqueado e identificado para comprobar sus permisos actuales antes de consultar o persistir datos. |
| Requerimientos | RF-10, RF-14, RF-15, RF-23, RNF-01, RNF-02. |

**Flujo principal**

- **CU-02.1:** El usuario solicita acceso a la aplicación interactiva y proporciona su nombre y contraseña.
- **CU-02.2:** El sistema identifica la cuenta sin distinguir mayúsculas y minúsculas en el nombre, verifica la contraseña mediante Argon2 y comprueba que la cuenta no esté bloqueada.
- **CU-02.3:** El sistema establece la identidad autenticada para las operaciones solicitadas. En la TUI la conserva en memoria; antes de cada operación se comprueban de nuevo la identidad, el bloqueo y los permisos actuales según RNF-02. Finaliza el caso.

**Flujos alternativos**

**CU-02.A1: Autenticación de un comando**

Desencadenante: paso CU-02.1, cuando el usuario solicita una operación mediante un comando de terminal, distinto de la creación del administrador inicial.

- **CU-02.A1.1:** El usuario proporciona las credenciales mediante `--user` y `--pass` en el comando solicitado.
- **CU-02.A1.2:** El sistema comprueba que ambos parámetros estén presentes.

Continuación: continúa en CU-02.2. Este flujo se ejecuta en cada comando, aunque una invocación anterior haya sido autenticada.

**CU-02.A2: Utilizar la identidad conservada en la TUI**

Desencadenante: paso CU-02.1, cuando el usuario solicita una nueva operación de consulta o persistencia en una TUI que ya conserva su identidad autenticada.

- **CU-02.A2.1:** El sistema recupera la identidad conservada en memoria y comprueba que corresponda a una cuenta existente y no bloqueada, sin solicitar de nuevo la contraseña.

Continuación: continúa en CU-02.3. El caso de uso solicitado comprueba los permisos actuales antes de acceder a sus datos.

**Flujos de excepción**

**CU-02.E1: Credenciales no válidas**

Desencadenante: paso CU-02.2, cuando no se identifica la cuenta o la contraseña no es válida.

- **CU-02.E1.1:** El sistema deniega el acceso y no ejecuta la operación solicitada.

Continuación: finaliza el caso sin autenticar al usuario.

**CU-02.E2: Faltan parámetros de autenticación**

Desencadenante: paso CU-02.A1.2, cuando falta `--user` o `--pass`.

- **CU-02.E2.1:** El sistema no ejecuta la operación solicitada e informa que se requieren ambos parámetros.

Continuación: finaliza el caso sin autenticar al usuario.

**CU-02.E3: Cuenta bloqueada**

Desencadenante: paso CU-02.2 o CU-02.A2.1, cuando la cuenta está bloqueada.

- **CU-02.E3.1:** El sistema deniega el acceso y no ejecuta la operación solicitada.

Continuación: finaliza el caso sin habilitar el acceso.

**CU-02.E4: Identidad conservada sin una cuenta existente**

Desencadenante: paso CU-02.A2.1, cuando la identidad conservada ya no corresponde a una cuenta existente.

- **CU-02.E4.1:** El sistema deniega la operación solicitada.

Continuación: finaliza el caso sin ejecutar la operación.

**Consideraciones**

- La autenticación no concede acceso por sí sola: cada operación comprueba roles y acceso al proyecto cuando corresponda.
- La única excepción a este requisito es [CU-01](CU-01.md). No se definen duración de sesión, cierre de sesión ni recuperación de contraseñas.
- El administrador bloquea o desbloquea cuentas mediante [CU-05](CU-05.md), conforme a RF-29. El estado actual se comprueba también antes de cada operación de una TUI ya abierta.
